# 产品问题定义：从“功能可用”走向“学习闭环可验证”

## 1. 问题陈述

本轮修改前，系统已经能完成课程问答、总结、练习和历史查询，但“接口能返回结果”还不能证明学习者能完成一次有效学习。首次进入缺少课程入口，练习在提交前直接暴露答案，检索也会把少量通用词重合误判成教材证据。因此，学习者难以判断系统当前能做什么、答案是否真的来自教材，以及练习后自己掌握了什么。

**目标用户：** 使用 Hello-Agents 教材学习智能体知识的学习者。  
**核心任务：** 选择章节，先建立框架，再针对疑问查教材，随后完成练习并回顾记录。  
**本轮目标：** 用小步、可回滚的改动补齐入口、练习提交、检索拒答和效果评测，而不是直接堆叠模型能力。

## 2. 本轮修改前的证据

1. 实际资料为第 1—12 章、67 小节、759 个知识文本块，与目标需求文档中的第 1—16 章不一致。
2. 默认运行能力是 BM25 + 教材原文摘录；Reranker 尚未实现，向量、混合检索和大模型生成不能被当成当前默认能力。
3. 修改前的冻结 20 题小样本中，6 个课程外问题全部返回了引文，拒答准确率为 0。
4. 修改前的练习页没有统一提交和结果汇总，参考答案可直接展开。
5. 自动化测试证明接口和流程能够运行，但不能单独证明检索相关性、回答忠实度或题目质量。

## 3. 根因假设

- 产品契约同时混合了“目标架构”和“当前交付”，团队缺少唯一的当前验收基线。
- 研发闭环以接口测试为终点，没有冻结问题集、原始逐题结果和可重复的效果评测命令。
- 页面按功能拆分，但没有按学习任务组织入口、下一步和练习反馈。

## 4. 本轮范围与结果

### 已纳入并完成

- 建立当前产品执行基线和后续优先级计划。
- 增加学习工作台、课程目录、章节入口和跨页面下一步。
- 练习改为“作答—提交—反馈—看答案”；单选题客观计分，简答题明确采用自评。
- 增加版本绑定的 20 题种子评测集、检索评测脚本和原始 JSON 报告。
- 为默认 BM25 增加证据充分性门控，减少课程外问题的伪证据。

### 明确不纳入

- 不把 20 题种子集包装成正式统计结论。
- 不在没有真实模型和对照评测时宣称混合检索、Reranker 或大模型效果已验收。
- 不在本轮补第 13—16 章，不改动“只保留知识正文、排除习题”的清洗边界。
- 不建设登录、多课程、自动批改简答题或长期学习画像。

## 5. 成功标准

| 层级 | 标准 |
|---|---|
| 本轮工程验收 | 全量自动化测试通过；学习工作台为默认入口；提交前不展示练习答案；评测脚本能从冻结 JSONL 生成逐题 JSON 报告 |
| 种子集诊断 | 20 题中 Recall@5 ≥ 0.90、Recall@10 ≥ 0.95、MRR@10 ≥ 0.75、课程外问题拒答准确率 ≥ 0.90、引用字段有效率 = 1.00 |
| 正式效果验收 | 另建 60—100 题人工复核集，固定验证集和未参与调参的留出集；达到同一指标门槛后，再决定默认检索链路 |
| 产品体验验收 | 学习者从首页进入章节总结、提问或练习不超过两次操作；练习提交后能看到完成情况、客观题结果、解析和教材来源 |

## 6. Build Risk Review

### 决策

**模式：** Feature-change  
**结论：Build small。** 已观察到可复现的伪证据和自测流程缺口，适合先做小步、可测试修复；更大范围的混合检索、Reranker 和课程扩充仍应先验证。

### R1：feature-fit——学习流程存在，但结果可信度与自测完整性不足

最大的失败假设是：只要补更多接口或模型，学习者就会觉得产品有效。现有证据只证明一名负责人明确表达未达预期，并证明两个具体流程缺口；它不证明更复杂架构一定有价值。

### 支持风险

- **R2 trust：** 关键词零散重合会把课程外内容包装成教材证据。
- **R3 evidence：** 20 题种子集已参与开发判断，只能作回归集，不能作正式盲测证据。
- **R4 scope：** 目标文档写 16 章，当前数据只有 12 章，容易重复产生“已完成”理解偏差。

### 需求层级

**L1：一名用户/负责人明确提出未达预期。** 当前没有重复用户请求、留存或收入证据，因此不把需求夸大为 L3/L4。练习答案提前展示和课程外伪证据是直接观察到的产品缺口，足以支持本轮小修复，但不足以支持大规模模型投入。

### 证据台账

| 编号 | 信号 | 强度 | 解读 |
|---|---|---|---|
| E1 | “我觉得当前项目情况还没符合我预期效果” | 弱：单一用户直接反馈 | 证明存在预期差距，不代表广泛需求。 |
| E2 | 两个课程外问题在修改前均返回引文；种子集拒答准确率为 0 | 强：可重复产品行为 | 证明可信度缺口真实存在。 |
| E3 | 修改前练习可直接展开答案，没有统一提交 | 中：直接流程观察 | 证明自测诚信受损，但未测量学习效果。 |
| E4 | 当前语料报告为 12 章，目标文档写 16 章 | 强：版本化文件证据 | 证明产品契约不一致。 |

### 低代码验证步骤

邀请 5 名目标学习者各完成同一任务：“选择一章—看总结—提出一个教材内问题和一个课程外问题—完成两题练习—核对来源”。不解释页面操作，记录完成率、误解当前能力的人数、课程外问题是否被识别、练习提交是否顺利。预先通过门槛：5 人中至少 4 人独立走完整流程，5 个课程外问题全部明确拒答，至少 4 人能正确说出当前是“关键词检索 + 教材原文摘录”。

## 7. 假设与待确认项

- **已验证：** 当前语料版本为 `caeb372d8f756b87`，范围是第 1—12 章；默认模式可在无外部模型时运行。
- **合理假设：** 本轮以第 1—12 章作为可交付课程范围，保持清洗结果不变。
- **待负责人决定：** 第 13—16 章是后续版本目标，还是从正式需求中移除。
- **待验证：** 真实学习者是否认为“总结—提问—练习—回顾”的首页路径比原功能导航更易理解。
