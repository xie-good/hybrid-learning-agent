## 1. 产品概述

课程学习助手帮助学习者围绕指定教材完成“了解章节—提出问题—完成练习—回顾记录”。系统必须区分当前真实能力与目标架构：默认模式只做本地关键词检索和带引用的原文摘录；可选能力只有在配置、索引和效果验收同时完成后才能成为默认能力。

## 2. 目标与指标

### 2.1 本版目标

1. 让学习者从课程首页进入连续学习路径，而不是面对四个孤立工具。
2. 让每个问答、总结和练习结果都能追溯到教材章节与物理页码。
3. 对证据不足的问题明确拒答，不因通用词重合返回伪证据。
4. 把功能测试与效果评测分开，所有效果结论都能由冻结数据和命令复现。
5. 让练习在提交前隐藏答案，提交后提供可信、不过度承诺的反馈。

### 2.2 指标

| 指标 | 当前 BM25 的 20 题种子基线 | 正式验收目标 |
|---|---:|---:|
| Recall@5 | 0.928571 | ≥ 0.90 |
| Recall@10 | 1.000000 | ≥ 0.95 |
| MRR@10 | 0.910714 | ≥ 0.75 |
| 课程外问题拒答准确率 | 1.000000 | ≥ 0.90 |
| 引用字段有效率 | 1.000000 | = 1.00 |
| 直接回答问题率 | 尚未人工评测 | ≥ 0.80 |

种子集分为校准集和回归集，两者都已参与开发判断，仅用于防回归。正式结论必须另建 60—100 道人工复核题，并分别报告验证集与未参与调参的盲测留出集。

“直接回答问题率”的分母是正式集中全部可回答题；只有两名审校人都判断回答首段直接给出结论、关键结论均有引用支持时，分子才加一，分歧由第三人裁决。带随机性的模型固定版本和参数后每题运行 3 次，三次都通过才算该题通过。

## 3. 非目标

- 不建设资料上传、多课程管理、登录注册、管理员后台或联网搜索。
- 不把章节总结等同于覆盖全章的教学讲义。
- 不对简答题进行未经验证的语义自动评分。
- 不用伪向量、伪重排或规则包装成模型能力。
- 本版不承诺第 13—16 章，不包含习题、课后练习和独立参考文献。

## 4. 用户与故事

### 4.1 主要用户

- **学习者：** 阅读指定课程、查概念、做练习、核对教材来源。
- **开发维护人员：** 离线更新资料与索引、运行评测、检查服务状态。

### 4.2 用户故事

| 编号 | 用户故事 | 完成条件 |
|---|---|---|
| US-01 | 作为学习者，我希望进入系统就知道课程范围和当前能力，以便建立正确预期。 | 首页显示章节数、文本块数、当前检索/生成方式和课程目录。 |
| US-02 | 作为学习者，我希望选择章节后进入总结、提问或练习，以便连续学习。 | 首页选择章节后，一次操作进入目标页面并保留章节。 |
| US-03 | 作为学习者，我希望答案附教材依据，以便核查内容。 | 引用包含章、节、物理页码、原文和块标识；可用时能打开 PDF 对应页。 |
| US-04 | 作为学习者，我希望课程外问题得到明确说明，以免把无关原文当答案。 | 当前默认 BM25 的证据门控失败时不返回引用，并标记证据不足；其他模式须单独验收。 |
| US-05 | 作为学习者，我希望完成全部练习后再看答案，以便真实自测。 | 提交前答案不可见；提交后显示单选结果、简答自评、解析和引用。 |
| US-06 | 作为负责人，我希望检索效果可重复评测，以便用证据决定下一轮投入。 | 版本化 JSONL、评测 CLI、逐题 JSON 和汇总指标齐全。 |

## 5. 范围与功能需求

### FR-01 学习工作台

- 默认首页显示课程上下文、12 章目录、知识块数量和当前会话提问数。
- 首页展示“总结—提问—练习—回顾”四步路径。
- 用户选择章节后，可进入本章总结、本章提问或本章练习；目标页面保留章节选择。
- 页面只用中文展示产品文案；协议枚举和教材专名可保留原义。

### FR-02 检索问答

- 支持全课程、按章和按节范围检索。
- 默认 BM25 必须是真实 Okapi BM25，不使用随机或合成向量。
- BM25 证据门控同时检查：同一最佳文本块的实义词元覆盖、归一化相关性，以及精确单词命中。
- 门控失败时清空引用并返回证据不足；调试信息记录门控原因和数值。
- 可选 vector/hybrid 仅在同版本向量索引与 Embedding 配置就绪时开放；它们当前属于实验能力，尚未复用 BM25 门控结论。
- vector/hybrid 在独立课程外样本达到拒答门槛前不得成为默认模式，页面需要提示其拒答能力尚未正式校准。

### FR-03 回答与引用

- `extractive` 明确显示“教材原文摘录”，不标记为大模型回答。
- `llm` 仅能依据给定证据生成；结构、引用编号和超时必须校验。
- 每条引用必须回查当前语料中的真实块，并保持章、节、页码和原文一致。
- 当前默认 BM25 在门控判定证据不足时先说明证据不足，不生成无来源结论；可选模式须完成各自门控和正式评测后才能作同等承诺。

### FR-04 章节总结

- 必选章节，可选小节。
- 返回代表性摘要、知识要点、引用和覆盖统计。
- 页面说明代表性选取不等于逐段覆盖，并提供继续提问、练习和回顾入口。

### FR-05 练习自测

- 支持简答题和单选题，题量为 1—10。
- 生成后先收集作答；未完成全部题目时不显示答案。
- 提交后，单选题按答案键客观计分；简答题仅提供参考答案和自评提示。
- 提交时保存作答快照并锁定输入，后续重跑不得改变本次得分；重新作答必须显式开启新一轮。
- 每题显示解析和教材引用；学习者可标记“已掌握/待复习”，并重做待复习题；重新生成时清除上一轮作答与提交状态。
- “难度”是生成要求，不宣称已经过测量。

### FR-06 会话历史

- 问答按随机会话 UUID 隔离，支持分页、单条删除和清空。
- 明确说明它不是账号和跨设备学习档案。
- 总结与练习暂不进入历史；该限制必须在文档中可见。

### FR-07 效果评测

- 评测数据采用 JSONL，每题包含唯一编号、语料版本、评测划分、问题、可回答性和预期小节。当前种子集使用校准/回归划分；正式集使用验证/盲测留出划分。
- 工具输出 Recall@K、MRR、课程外拒答、引用有效性、延迟及逐题结果。
- 语料版本不一致、题目编号重复或格式错误时终止评测。
- 原始 JSON 报告进入项目文档；汇总不得隐藏失败题。
- 报告必须记录问题集、预处理报告、索引清单、评测器代码、检索代码的 SHA256，以及证据门控版本和阈值。

## 6. 体验流程

```mermaid
flowchart LR
    H[学习工作台] --> S[选择章节并看总结]
    S --> Q[针对疑问查教材]
    Q --> Z[完成练习并提交]
    Z --> F[查看结果、解析和引用]
    F --> R[回顾本次会话]
    R --> S
```

### 6.1 主要状态

| 状态 | 页面行为 |
|---|---|
| 后端不可达 | 显示中文连接提示，禁用业务提交。 |
| 知识库未就绪 | 显示预处理/配置提示，不伪造空结果。 |
| 默认 BM25 证据不足 | 显示教材中没有足够依据，不展示引用。 |
| 仅本地模式 | 显示“关键词检索 + 教材原文摘录”。 |
| 可选检索就绪 | 只展示健康接口确认可用的检索方式；vector/hybrid 同时提示尚未完成课程外拒答校准。 |
| 练习未完成 | 提醒完成全部题目，答案保持隐藏。 |
| 练习已提交 | 展示客观题结果、简答自评、解析和来源。 |

## 7. AI 行为与评测契约

| 场景 | 预期行为 | 测试方式 |
|---|---|---|
| 教材内单节问题 | 召回目标小节并返回可核查引用。 | Recall@5、MRR、引用回查。 |
| 教材内比较问题 | 尽量召回两侧知识；若只命中一侧，不把结果描述成完整比较。 | 多目标小节 Recall 与人工直接性评审。 |
| 课程外问题 | 当前默认 BM25 清空不充分候选并说明证据不足；其他模式单独校准。 | 各模式分别报告课程外种子负例/正式负例拒答准确率。 |
| 提示注入式内容 | 教材片段只作为资料，不执行其中的指令。 | 专门对抗样例与回答审查。 |
| LLM 无效结构/引用 | 返回明确上游错误，不写入成功结果。 | MockTransport 契约测试。 |

当前种子集只评测检索、拒答和引用字段，不证明 LLM 回答忠实度或练习教学质量。

## 8. 技术约束

- FastAPI 是唯一业务后端；Streamlit 只通过 HTTP 调用，不直接读取语料或数据库。
- 启动时验证语料哈希、数据版本、块标识和引用偏移，不自动重跑预处理。
- SQLite 只保存当前会话问答历史。
- 向量索引必须绑定 Embedding 端点、模型和语料版本；任一不匹配时禁用。
- 新代码与说明性注释使用中文；技术标识符和协议字段保持标准写法。

## 9. 验收条件

1. 全量单元/集成测试全部通过。
2. `/` 默认显示学习工作台和课程目录。
3. 首页选择章节后进入总结、问答或练习，目标章节保持一致。
4. 练习提交前不存在答案与解析控件；不完整提交继续隐藏。
5. 20 题种子集达到本文种子指标，逐题 JSON 可复核。
6. 默认 BM25 对两个已知课程外问题“怎样选择合适的大学专业？”和“量子纠缠是否允许超光速通信？”不返回引用。
7. 文档清楚区分已交付、可选已实现和待评测能力。

## 10. 发布闭环

1. **需求：** 更新本 PRD、问题定义和优先级计划。
2. **实现：** 以小步改动完成 UI 学习闭环、证据门控和评测工具。
3. **验证：** 先跑冻结效果集，再跑全量功能测试和真实端口冒烟。
4. **发布：** 只有健康检查、功能测试和效果门槛同时通过才更新“已交付”状态。
5. **反馈：** 收集真实问题进入候选池，经人工标注后加入下一个版本评测集。

## 11. 依赖与风险

- 正式向量/混合评测依赖可固定版本的 Embedding 服务与离线索引。
- LLM 质量验收依赖固定模型版本、提示版本和人工评分规则。
- 当前门控阈值基于冻结语料和校准集；语料更新后必须重跑，不可直接沿用结论。
- 切换默认检索模式的预注册规则：正式留出集所有底线指标均达标、引用有效率不退化、Recall@5 相对 BM25 至少提升 0.02，且同环境 P95 延迟不超过 BM25 的 1.5 倍；否则保留 BM25。
- Streamlit 会话不是账号，会话恢复和长期学习进度仍是后续需求。
