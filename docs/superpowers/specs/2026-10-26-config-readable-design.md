# 配置代码可读性设计

## 目标与范围

用户已要求开始修改：代码简洁、易懂、中文注释，并完成测试、文档和回归闭环。本轮只简化配置及其调用入口，不改检索算法、接口契约、预处理结果或实际 `.env`。

## 方案

- 保留 `Settings` 数据类、现有 14 个字段、默认值和环境变量名，不增加依赖。
- `Settings()` 只表达默认值或显式参数；字段直接写默认值，不使用 `field(default_factory=lambda...)`。
- `Settings.from_env()` 集中读取环境变量，显式转换路径、超时和跨域列表。应用工厂与离线索引入口统一调用它。
- `.env` 仍在导入配置模块时加载，已有进程环境变量优先；相对路径仍从项目根目录定位。
- 保留 `dataclasses.replace()`、显式配置注入和代理判断；保留全部校验规则，错误说明改为中文。
- 不引入嵌套配置类、反射、动态字段映射或配置框架。

## 验收

默认 BM25 + 原文摘录行为不变；环境变量覆盖、可选模型、路径及空值语义不变；显式配置不受环境变量影响。新增配置单测先失败后通过，原有全量测试通过，13 个操作与前端真实 HTTP 冒烟通过。在额外副本中回滚并验证原始哈希与旧行为，主项目保留修改。

## 文件职责

`backend/config.py` 保存默认值、环境读取和校验；`backend/main.py` 与 `pipeline/build_index.py` 使用显式环境入口；`tests/test_config.py` 验证行为；`README.md` 与 `.env.example` 解释配置分组、读取时机和调用方式。
